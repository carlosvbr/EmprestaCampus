#AutenticaçãoEsta documentação detalha os fluxos, as estratégias e a implementação prática dos mecanismos de autenticação do projeto EmprestaCampus, abrangendo tanto o consumo via API REST quanto a interface web tradicional.---### 1. Arquitetura Híbrida de Autenticação (SoC)A aplicação adota o princípio de Separação de Conceitos (SoC) para atender a diferentes tipos de clientes:API REST (Stateless): Destinada a integrações externas ou front-ends desacoplados, utilizando tokens de acesso baseados em JSON Web Tokens (JWT).Interface Web (Stateful): Destinada ao painel de validação visual da disciplina, utilizando o sistema nativo de sessões e cookies do Django.### 2. Fluxo de Autenticação Web (Stateful)Implementado na função `login_view` e associado à rota web (`entrar/`), gerencia o acesso de usuários à interface HTML:Restrição de Método HTTP: O fluxo valida estritamente requisições do tipo `POST`, garantindo que credenciais sensíveis trafeguem no corpo da requisição e não na URL.Validação de Credenciais (`authenticate`): O Django processa a consulta de forma segura por meio da função `authenticate()`, que compara o hash da senha enviada com o armazenado no SGBD PostgreSQL.Criação de Sessão (`login`): Caso as credenciais sejam válidas, a função `login()` acopla o usuário à sessão ativa do servidor e emite um cookie de sessão seguro (`HttpOnly`).Redirecionamento Pós-Login: O sistema executa um redirecionamento controlado via `redirect('home')` para o endpoint protegido (`home_view`), confirmando o sucesso da transição de estado.### 3. Fluxo de Autenticação via API REST (Stateless - JWT)Utiliza a biblioteca `djangorestframework-simplejwt` para gerenciar o ciclo de vida dos tokens de acesso:Obtenção de Token (`login_api`): Mapeado na rota `login/` (`TokenObtainPairView`), valida as credenciais enviadas via payload JSON e retorna um par de tokens (`access` token de curta duração e `refresh` token).Renovação de Token (`login_renovar`): Mapeado na rota `login/renovar/` (`TokenRefreshView`), permitindo que o cliente obtenha um novo token de acesso utilizando o `refresh` token, sem necessidade de reautenticação com senha.### 4. Registro e Acesso Público (`RegistroView`)O cadastro inicial de novos usuários é tratado pelo endpoint público `RegistroView` (herdando de `generics.CreateAPIView`):Permissão Aberta (`AllowAny`): Configurado explicitamente para permitir o acesso de novos usuários sem a exigência de um token prévio.Segurança na Criação: A requisição delega a persistência ao `RegistroSerializer`, que invoca o método de hash de senha antes de efetivar o registro na tabela de usuários.### 5. Tratamento de Erros e Feedback VisualO sistema utiliza o Django Messages Framework para gerenciar o feedback ao usuário:Em caso de falha na autenticação web, a aplicação captura o erro e injeta a mensagem genérica `messages.error(request, 'Credenciais inválidas...')` no template `login.html`.O front-end exibe dinamicamente o alerta visual em caso de erro, guiando o usuário sem expor falhas de segurança do sistema.### 6. Resumo dos Fluxos de AutenticaçãoTipo de Fluxo	Endpoint / Rota	Tecnologia / Componente	Finalidade PrincipalAutenticação Web	`/api/usuarios/entrar/`	`authenticate()` + `login()`	Acesso via navegador com sessão e cookies.Geração de Token JWT	`/api/usuarios/login/`	`TokenObtainPairView` (SimpleJWT)	Autenticação stateless para APIs e clientes externos.Renovação de Token	`/api/usuarios/login/renovar/`	`TokenRefreshView` (SimpleJWT)	Estender a sessão da API sem reenvio de credenciais.Cadastro Público	`/api/usuarios/registro/`	`RegistroView` (`AllowAny`)	Porta de entrada para novos cadastros de usuários.Redirecionamento	`/api/usuarios/home/`	`home_view` (`HttpResponse`)	Validação visual do caminho feliz pós-login.### 7. ConsideraçõesOs mecanismos de autenticação implementados equilibram a flexibilidade moderna de APIs baseadas em tokens com a robustez e segurança de uma aplicação web tradicional baseada em sessões do Django, atendendo integralmente aos requisitos do projeto.
